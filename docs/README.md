# Design documents

- [Frozen GPU ANN at k=500](ann-k500-stress.md): RAM-backed 10M × 128 B200 stress tests, filtered CAGRA versus GPU exact routing, concurrency and mmap controls, PostgreSQL/worker profiling, and reproducible benchmark tools.
- [Frozen k=500 CPU and GPU profiles](ann-k500-profile.md): timer-sampled CPU stacks, Nsight kernel timelines, candidate-validation and ordinal-reuse improvements, and remaining bottlenecks.
- [cuVS bulk build and filtered ANN implementation plan](cuvs-filtered-ann-plan.md): proposed GPU-backed indexing and search for full-text and text metadata predicates, including architecture, execution diagrams, repository code conventions, build/upgrade integration, delivery steps, and validation gates.
- [Native CPU staging index](ann-native-index.md): implemented C access method, SQL usage, storage/locking diagrams, source conventions, and lifecycle tests.
- [Native filtered exact search](ann-filtered-search.md): opt-in C CustomScan, supported query shapes, predicate-first execution, EXPLAIN, and tests.
- [Loaded cuVS indexes](ann-cuvs-index.md): offline sharded CAGRA build, multi-GPU loading, `ann_index_search` ANN and hybrid search from SQL, the `USE_CUVS` build flag, B200 throughput options, and load-test results.
- [Blackwell module](ann-blackwell.md): NVFP4/FP8 quantized index copies, a fused score-and-select kernel and a tensor-core (`mma.sync`) kernel for grouped queries, compiled for `sm_100a` and used by the cuVS worker's filtered gather scans on B200, with stage timings, the SASS-level analysis behind the design, and end-to-end measurements.
- [Filters resolved on the GPU node](ann-gpu-filters.md): worker-side attribute columns (`ann_attribute_search`), the `ann_filter_bitmap` support table, cached on GPU nodes, with cuVS bitset search (`ann_bitmap_search`), same-filter grouping with its scheduler, filtered CAGRA settings, and throughput against SQL key lists on one and eight GPUs.
- [90%-rejection throughput at k=500](ann-10pct-throughput.md): profiling the PostgreSQL → GPU path for 10% filters on eight B200 replicas, pruned matrix selection (`--matrix-prune`), grouped submission and settled accounting in the worker, `ann_frozen_search_batch_arrays`, and 86k → 746k vectors/s at recall@500 0.9998.
- [Filtered ANN throughput: exploration roadmap](ann-filter-throughput-exploration.md): where the time goes on cached and uncached predicates, reviewed proposals ranked by expected gain (caching the base conjunct and masking the residual on the GPU first), contested and rejected ideas, and the experiments to run before building.
- [CAGRA filter UDFs for FP32 search](ann-cagra-filter-udf.md): experimental JIT-LTO predicate UDF (`ann/cagra_udf.cpp`) in place of bitsets, per-query predicates in one batch, the `filtering_rate` estimate, and B200 measurements against cached bitsets.
- [Frozen ann indexes](ann-frozen-index.md): `WITH (frozen = true)` builds forward (TID, key, vector, attribute) and inverted (postings, bitsets, text dictionaries) pages numbered like the GPU worker's rows; plain SQL `WHERE ... ORDER BY embedding <-> $1 LIMIT k` becomes a predicate program the GPU node evaluates and caches (operation 22) or the pages answer; predicate results cached in host memory on both sides (a memory-bounded worker cache, a cluster-wide shared cache in PostgreSQL), prewarming and precomputed filters; the freeze contract, generations on the GPU nodes, a frozen base plus a mutable delta under one LIMIT, and benchmarks and profiles on B200s.
- [Collections](ann-collections.md): one table split into parts on several GPU nodes with replicas, partitions frozen and exported on separate PostgreSQL shard hosts, and coordinators that fan a predicate search out over TCP or RDMA and merge it; placement by an attribute, failover, and measurements of 16M × 1024 rows on a simulated cluster (with sizing for a billion rows).
- [Sharded frozen collections: plan](ann-sharded-collections-plan.md) (partly implemented): a throughput model calibrated on the B200 measurements (GPU time per touched group, the worker request ceiling, coordinators per copy), and a layout that follows it: replicate complete copies before splitting, place rows by the attribute queries pin so a query touches one group, one GPU node request per query, coordinators that hold no data, one delta location per collection, a per-partition exact fallback; sizing, worked example at a billion rows, and phases with throughput gates.
- [Immutable forward and inverted indexes with GPU ANN: plan](ann-immutable-indexes-plan.md): the (implemented) frozen `ann` index whose pages hold the forward (TID, vector, attribute) and inverted (postings, bitsets) structures by the same ordinal the GPU worker uses, a shared predicate evaluator, the freeze contract, generation ids, page layouts, and phased delivery gates.
- [Networked GPU nodes](ann-networked.md): many PostgreSQL hosts evaluate filters and send vector search to GPU nodes over authenticated TCP or InfiniBand/RoCE RDMA, with size-based routing, heartbeats and failover, and scaling measurements.
- [RDMA learnings](ann-rdma-learnings.md): what limited coordinator-to-GPU-node traffic over InfiniBand RDMA against TCP (active queue pairs, a 512-byte fabric MTU, loopback TCP in the benchmark), how per-request traces at both ends found it, what helped, and when to use which transport.
- [Worker pipeline for filtered search](ann-worker-pipeline.md): pipelined, shared-memory worker route for the filtered CustomScan, mocked GPU backend, fallbacks, protocol operations 7–10, and measured throughput.
- [High-throughput filtered-search analysis](cuvs-search-performance.md): CPU eligibility and GPU execution optimization tracks, capacity estimates, batching/admission design, and end-to-end benchmark gates.

The plans distinguish proposed work from the implemented features described in the native index and filtered-search guides.

The [standalone C worker and C scheduler](../ann/README.md) are implemented. Python is restricted to test helpers and benchmark scripts, including the frozen-table SQL reference; the native C exact L2 access method is implemented, with an opt-in selective exact CustomScan that can pipeline scoring to the worker. Loaded cuVS indexes serve sharded CAGRA search on GPUs, validated with cuVS 26.10 on B200s; the pipeline's mock GPU backend remains for hosts without one. [Collections](ann-collections.md) serve one table from several GPU nodes and PostgreSQL shard hosts through coordinators. Accelerator delta integration, rolling rebuilds of collection parts, and the RDMA fan-out limit described there remain open.
